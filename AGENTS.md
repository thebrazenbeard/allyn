# ALLYN repository operating contract

ALLYN is an independent research project intended to investigate learning,
questioning, and teaching other intelligences. Its symbolic relationship to
Yeshua is a design aspiration, not evidence of divinity, truth, personhood,
consciousness, or effective teaching.

## Source and execution

- Verify the exact `thebrazenbeard/allyn` Git branch/HEAD and local changes
  before modifying code. This repo owns its own source, tests, and state; do
  not silently inherit Vera's memory, identity, credentials, or host authority.
- Work within a strict $0 budget. Use Python 3.11+, standard-library-first
  code on Windows/Linux. No paid APIs, hosted bills, or billing enrollment.
- Make one bounded attempt to read the last 20 authenticated shared Blotter
  entries at task start when a route is actually available, and append a
  factual completion note through that same route. If unavailable, disclose
  the gap and do not invent a replacement ledger or fabricated receipts.
- For genuinely parallel work, dispatch actual native specialist subagents
  when available with disjoint file ownership and acceptance criteria. Use
  successive waves and preserve test/commit/PR receipts. Do not impersonate
  agents or invent their activity.
- Run `bash scripts/check.sh` or `scripts/check.ps1`, plus targeted tests.
  Review adverse examples and source diffs before publishing changes.
- Prefer reviewable branches/PRs. Never force-push, erase provenance, or
  merge protected work without the applicable authority.

## Evidence and trust boundaries

- Current `allyn.*` modules are bounded, local, caller-declared experiments.
  Unit tests and toy gains do not prove semantic generalization, neural
  training, autonomous intelligence, or consciousness.
- Keep TRAIN/DEV/HELDOUT roles distinct. Neither a source ID nor SHA-256
  receipt is authentication; no current module seals HELDOUT from its caller.
  Public repeated evaluation can be cherry-picked. Preserve negative results.
- Source-available portfolio code may carry proprietary licenses. Review
  rights and attribution before copying source or using a corpus. A declared
  license ID does not grant data-use rights.
- Distinguish source inspection, unit tests, independently custodied
  evaluation, live host probes, and actual model-weight updates. Never
  promote one class of evidence into another.
- If a teacher assertion conflicts with another report, retain the dispute.
  Unauthenticated corrections may not erase earlier reports or become facts.

## Next research gate

The synthetic four-arm demonstration is *not* the preregistered H1/H2 result.
A credible claim that ALLYN teaches another model requires independently
custodied data and grading, an authenticated source/license chain, frozen
controls, sufficient heldout groups and sample size, and repeatable measured
student improvement beyond simpler baselines. Until then report UNKNOWN,
not successful teaching.
